## 1. 它是什么

一个本地网页应用，把 **Codex CLI**、**Claude Code**、**Pi**、**DeepSeek Harness（dsh）**、**Hermes** 五个命令行 AI 工具散落在各处的历史会话，聚合成一个可搜索、可阅读、可继续对话的界面。

它**不落新数据、不改动已有文件**（除非你主动删除），只读这五家工具自己写的会话文件：

| 工具 | 会话文件位置 |
|---|---|
| Codex CLI | `~/.codex/sessions/**/*.jsonl`（标题另读 `~/.codex/session_index.jsonl`） |
| Claude Code | `~/.claude/projects/**/*.jsonl` |
| Pi | `~/.pi/agent/sessions/**/*.jsonl`，或 `$PI_CODING_AGENT_SESSION_DIR` |
| DeepSeek Harness | `~/.dsh/sessions/**/session.v4.jsonl.zstd`（zstd 压缩的多帧 JSONL） |
| Hermes | `~/.hermes/webui/sessions/*.json`、`~/.hermes/sessions/session_*.json` |

（Windows 下 `~` 即 `%USERPROFILE%`，路径结构相同。）

所以：**你平时怎么用这五个工具，这里就怎么显示**；反过来，这里的操作也会真实作用到那些会话上——「恢复」是真的续上那次对话，「删除」是真的把文件移进回收站。

> **关于名字**：**OpenSession** = *open* + *session*。核心动作就两件——把散落各处的会话**打开**（查看、搜索、导出），
> 以及把旧会话重新**打开**继续聊（页面内恢复 / 终端恢复）。名字取自动作本身，不是"馆"或"仓库"那类收藏式命名。

## 2. 安装

需要 **Node.js 18+**。零 npm 依赖，不装任何包。

先拿到代码：

```bash
git clone https://github.com/1670295969/open-agent-session.git opensession
cd opensession
```

（本机 22 端口常被墙，克隆/拉取失败时改用 SSH 443：
`GIT_SSH_COMMAND="ssh -p 443 -o HostKeyAlias=ssh.github.com" git clone git@ssh.github.com:1670295969/open-agent-session.git`）

再跑一次纯手动模式确认能用（不需要装任何东西）：

```bash
node opensession-server.js
# OpenSession: http://localhost:8347
```

确认页面能打开、会话列得出来，再按平台一键安装（服务常驻 + 开机自启 + 桌面图标）：

### Linux

```bash
./install.sh                # 装服务 + 自启 + 桌面图标 + 左侧导航栏固定
./install.sh --status       # 只看状态，不改任何东西
./install.sh --uninstall    # 撤销（保留你的数据与脚本）
```

装完是三层保障：

| 层 | 机制 | 效果 |
|---|---|---|
| 开机自启 | systemd user unit（enabled） | 登录即起 |
| 免登录自启 | `loginctl enable-linger $USER` | 没人登录也常驻 |
| 崩溃自愈 | `Restart=on-failure`，3 秒后重拉 | 挂了自动恢复 |

### macOS

```bash
./install-mac.sh              # launchd LaunchAgent + 桌面 .app + 图标
./install-mac.sh --status
./install-mac.sh --uninstall
```

产物落在 `~/Library/LaunchAgents/com.opensession.viewer.plist`、桌面与 `~/Applications` 的
`OpenSession.app`、日志 `~/Library/Logs/opensession/`。不写系统目录，不需要签名或公证。

### Windows

**PowerShell** 里执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1   # 桌面快捷 + 开机自启 + 立即启动
.\install.ps1 -Status
.\install.ps1 -Uninstall
.\install.ps1 -NoAutoStart     # 不设自启
.\install.ps1 -NoDesktop       # 不建桌面快捷
```

不注册系统服务、不改 HKLM。常驻靠当前用户的启动文件夹，卸载就是删两个 `.lnk` 和一个
`%USERPROFILE%\.opensession` 目录，也可以在「任务管理器 → 启动」里自己关掉。

> **重装提示**：升级 Node / 换机器后如果服务起不来，直接重跑一遍安装脚本即可——它是幂等的，
> 会重新探测 Node 路径并修好服务配置。

## 3. 打开

| 方式 | 入口 | 说明 |
|---|---|---|
| **桌面图标** | 双击「OpenSession」 | 最快 |
| **左侧导航栏 / Dock** | 点已固定的图标（仅 Linux） | 与桌面图标同一入口 |
| 应用菜单 / 聚焦搜索 | 搜 "OpenSession" | |
| 命令行（独立窗口） | `opensession-open --app` | 1900×1150 无地址栏窗口，像个原生应用 |
| 命令行（普通标签页） | `opensession-open --tab` | 在你现有浏览器里开一页 |
| 带筛选启动 | `opensession-open --app --tool=claude` | 只显示 claude 会话 |
| 带搜索启动 | `opensession-open --app --q=关键词` | 预填搜索框 |
| 收起列表启动 | `opensession-open --app --noside` | 启动即占满窗口 |
| 直接开浏览器 | 手动访问 `http://localhost:8347` | 服务得先起着 |
| 装成独立 App | Chrome 地址栏右侧「安装」图标 | 见下方说明 |

`opensession-open` 会先探活，服务没起就自己拉起来，不用手动起服务。

**改窗口尺寸：**

```bash
OPENSESSION_WIN_W=1600 OPENSESSION_WIN_H=900 opensession-open --app
```

**装成独立 App（PWA）：**

页面自带 `manifest.webmanifest` 与一个不缓存的 service worker，Chrome / Edge 会认为它
「可安装」。点地址栏右侧的安装图标，或在菜单里选「安装 OpenSession / 固定到任务栏」，
就会得到一个用**自己的图标**、没有地址栏的窗口，和 `opensession-open --app` 效果接近。
好处是不用依赖启动器脚本，坏处是窗口尺寸由浏览器记忆、不受 `OPENSESSION_WIN_W/H` 控制。

service worker 刻意**不缓存任何内容**（只是透传），所以列表不会看到过期数据；
断网时页面打不开，这与本工具「读本机会话文件」的定位一致。

**为什么不建议从脚本 / CI 里拉起窗口**：那样启动的 GUI 进程往往没有真实的桌面会话
（缺 `DISPLAY` / DBus），窗口不会出现。日常请点图标或 `opensession-open`。

### 隐藏左侧列表

标题栏的 `«` 按钮可以收起左侧列表，让正文占满整个窗口（读长对话、对照代码时有用）。

| 操作 | 效果 |
|---|---|
| 点标题栏 `«` | 收起左侧列表 |
| 点左上角浮出的 `» 会话列表` | 展开回来 |
| `Ctrl+B`（macOS 也可 `Cmd+B`） | 来回切换 |

折叠状态会被记住，下次打开还是收起的样子；想恢复默认（展开）就再点一次 `»`。
在搜索框 / 输入栏里打字时 `Ctrl+B` 不生效，不会影响正常输入。

## 5. 查看会话

点左侧任意一条会话，右侧显示完整对话：

- **用户提问**是有底色的圆角卡片（宽度随问题长短收缩，短问题不会拉成一条大色块）
- **助手回答**是裸文字，不套底色——答案通常很长，套卡片会像挤在盒子里
- 每条消息左侧有一条细竖线，颜色随角色区分（用户蓝、助手灰），悬停会亮起来，
  长会话里靠它定位当前读到哪条
- 角色行是「色点 + 角色名 + 时间」；时间只显示 `时:分`，跨天的补上 `月-日`，
  悬停能看到完整时间戳
- 同一轮的后续动作（一句话之后接连几次工具调用）不再重复画角色行，
  只在组首标一次，读起来像「一次回答里的几个步骤」而不是一堆碎片
- 助手调用工具的那一步默认**不显示**（一次回答常有十几个调用，会盖住正文）；
  顶栏 `⚙ 命令` 可随时打开，见下面「工具调用」
- sidechain（子代理对话）会额外标注 `sidechain`
- 正文默认按 **Markdown** 渲染：标题、粗体、列表、表格、引用、链接、围栏代码块（右上角带**复制**按钮）

正文宽度**撑满右侧**，宽屏下不会留出大片空白。助手回答不限高（整页一起滚），
用户消息超过一屏时在自己的卡片里滚动——粘贴一大段日志进来不会把整页撑开。

正文右上角的 `M↓ Markdown` 按钮可以一键切回**纯文本**（保留原始换行缩进），看被误解析的原始内容时用。

### 思考过程

模型的推理过程（thinking / reasoning）显示为助手消息上方的一条折叠行：

```
▸ 💭 思考过程  1.8k 字
```

**看历史会话时默认收起**，点一下那一行才展开，再点收起。折叠状态下只占一行，不会把正式回答挤走。

**在页面里继续对话时是反过来的**：思考过程一边生成一边显示（默认展开、带「进行中」标记），
回答跑完后自动收起成一行摘要。等待期间你能直接看到模型在想什么，不用干等。
中途自己点过那一行，收尾时就不会再自动收起，按你的选择来。

哪些工具能看到：

| 工具 | 思考内容来自 | 说明 |
|---|---|---|
| Claude Code | `thinking` 块 | 最完整，历史会话与实时对话都有 |
| Pi | `thinking` 块 | 历史会话完整；**实时对话看不到**（上游加密返回，本地解不开） |
| Hermes | `reasoning_content` | 推理模型（如 DeepSeek）才有 |
| Codex | `reasoning` 的 `summary` | 正文被加密，只剩要点式摘要，通常只有几十字；且不是每轮都有 |
| DeepSeek Harness | `reasoning` 块 | 明文完整（早前文档写"看不到"是错的，已更正） |

两个要知道：

- 折叠时内容虽然还在页面里，但浏览器自带的查找（`Ctrl` / `⌘` + `F`）**搜不到**，
  得先点开那一行。
- 特别长的单条思考会在 2 万字处截断（和正文同一档上限），末尾标 `…[思考已截断]`。
  原文仍完整存在会话文件里。

### 工具调用（默认隐藏，可一键显示）

🔴 **默认不显示**。助手的工具调用（`exec_command` / `write_stdin` / `get_public_file` 这类）
在正文里一律不铺 —— 一次回答背后常有十几个调用，会把真正要读的内容挤没。

想看的时候点顶栏的 **`⚙ 命令`** 按钮（按钮上的数字是这条会话有多少次调用）：

```
⚙ 命令 927     ← 隐藏状态，927 次调用没显示
⚙ 命令         ← 显示状态
```

打开后每条调用显示成一行 chip：

```
▸ ⚙ exec_command("for dir in \"$out\"/*_5555; do echo \"…")
```

**点这一行**，展开完整命令原文（保留换行和缩进，多行 shell 脚本能直接照着看）：

```
▸ ⚙ exec_command("for dir in \"$out\"/*_5555; do echo \"…"        ⧉ 复制命令
  for dir in "$out"/*_5555; do
    echo "== $dir"
    ls -1 "$dir" | head
  done
```

- 显示 / 隐藏的偏好会被记住，下次打开还是同一套读法（存在浏览器本地）。
- 隐藏时上方「N 条」按**看得见的消息**算，悬停可以看到原始记录条数。
- 只有**摘要装不下**的调用才可展开（多行脚本、超长参数）。短命令（`ls`、`git status`
  这类）直接显示完整内容，没有折叠箭头，不用多点一次。
- 一次消息里有多个调用时，标题会标出「展开 N 条命令」，展开后每条一个块，各带复制按钮。
- 展开区**限高**并内部滚动：实测单条命令能到 50 行，不限高会把整段正文顶出屏幕。
- 命令里有敏感信息（密钥、内网地址）时注意：这里是本地会话原文，导出 MD 也会带上。
- 「命令」也能被**全文搜索**搜到（见第 7 节）。命中一条被隐藏的命令时，
  会自动切到显示状态并展开那一条，不用手动点。
- 导出 MD 时完整命令一并导出（不受显示开关影响），同样放在 `<details>` 折叠块里。

进度条上方的两行信息说明这条会话的来历：

```
📁 /home/you/work/myproject          ← 会话当时的工作目录（点一下可以浏览这个目录）
$ codex resume --no-daemon 01a2...   ← 可以复制到终端跑的命令
```

### 文件路径与链接（点开就能看）

正文里的**本地路径**和**网络链接**都可以点：

```
修改了 BackCarStatusUtils.kt:44  ← 青绿虚线，点开在弹窗里预览，定位到第 44 行
参考 https://ui.perfetto.dev/    ← 蓝色，点开在新标签页
```

**本地文件**点开后弹出一个预览窗：

| 内容 | 预览方式 |
|---|---|
| 代码 / 文本 / 日志 | 目标行附近的 400 行，左边带行号，命中行橙色高亮；底部「上一段 / 下一段」翻页 |
| 图片 | 直接显示 |
| 目录 | 列出里面的文件，可以继续往里点 |
| 二进制（`.so`、可执行文件） | 只给大小和时间，提示用编辑器打开 |

预览窗右上角两个按钮：

- **`✎ 编辑器`** —— 用本机编辑器打开并定位到那一行（依次尝试 `code` / `codium` /
  `cursor` / `subl` / `idea`；都没装就交给系统默认程序，只能打开、定位不到行）
- **`⧉ 路径`** —— 复制这个路径

`Esc` 或点窗外关闭。

能点的路径形式：

| 写法 | 说明 |
|---|---|
| `/home/x/a.kt:44` | 绝对路径 + 冒号行号 |
| `/home/x/a.log#L96` | 绝对路径 + `#L` 行号（GitHub 风格） |
| `~/work/a.kt` | `~` 会展开成你的主目录 |
| `out/report.md` | 相对路径按**会话的工作目录**解析 |
| `/home/x/a.kt:44:12` | 列号会被忽略，只定位到行 |

两处不会变成链接，是故意的：

- **通配符**（`decoded/*.log`、`/data/anr/trace_*`）—— 点了只会「文件不存在」
- **类似路径的普通文字**（`24/7`、`TCP/IP`、`和/或`、`/v1/chat/completions`）——
  相对路径必须带文件扩展名才认，绝对路径的顶层目录必须是 `/home` `/data` `/tmp`
  这类真实根目录，否则正文会满屏假链接

顶栏的 `📁 工作目录` 也能点，直接浏览那个目录 —— 相对路径解析偏了的话，从这里能一眼看出问题。

### 两处刷新

| 按钮 | 位置 | 作用 |
|---|---|---|
| `↻` | 左上标题栏 | 重取整个会话列表，同时重读当前会话。若会话已被外部删除，会提示并回到空白页 |
| `⋯ → ↻ 刷新本会话` | 正文操作栏的 `⋯` 菜单 | 只重读当前会话文件，保留你正在看的页码 |

终端里刚聊完，回来点一下就能看到新内容。

> 正文操作栏只常驻四个东西：`⚙ 命令`、`M↓ Markdown`、`⋯`、`▶ 终端恢复会话`。
> 刷新 / 复制命令 / 导出 / 页面内继续都在 `⋯` 里 —— 以前七个按钮平铺，1024px 窗口下
> 路径和恢复命令都被挤成省略号。窗口很窄时按钮只显示图标，鼠标悬停能看到全名。

### 空会话

有些会话点开一片空白——这不是 bug，文件里确实没有对话。典型情况是 `codex exec` 启动后
0.7 秒就被中断，只有元数据没有正文。识别出来后会：

- 列表标题显示 `(空会话 · 无对话内容)`，并带一个虚框「空」标签
- 正文区给出说明卡片，告诉你成因和可选项（恢复 / 删除）

## 6. 搜索 / 筛选 / 分页

### 搜索：两种模式

搜索框右侧有个按钮，在 **`标题`** 和 **`全文`** 之间切换（默认 `标题`）：

| 模式 | 搜什么 | 速度 | 适用 |
|---|---|---|---|
| 标题 | 会话标题 + 工作目录 | 即时 | 记得会话叫什么、在哪个目录 |
| 全文 | 每条消息的正文 + 思考内容 + **工具命令** | 首次 2–4 秒，之后几十毫秒 | 只记得「当时说过某句话」，或想找「那段跑 xx 的脚本」 |

输入即搜（全文模式停手 0.3 秒后自动搜），也可以按 **Enter 立即搜**。`Esc` 清空关键词。

**全文模式为什么第一次慢**：它要把所有会话文件都读一遍（实测 171 个会话、原始 225MB）。
第一次搜会显示「搜索中…首次需要 2–4 秒」，之后就快了——同样的会话再搜只需十几毫秒，
因为解析结果被缓存了（会话文件有变动会自动重新解析）。

结果长这样：每条命中会话一张卡，标题行显示命中次数，下面是若干条**带高亮的上下文片段**。
片段前会标出来源（`思考` / `命令`，正文的命中不标），因为命中的不一定是对话正文——
搜到命令里的片段时，那段脚本不是谁说的话。

点任意片段直接跳到那条消息的位置并闪一下。命中**折叠内容**时会自动展开，否则滚过去只看到一行摘要：
命中的是思考内容就展开思考块，命中的是工具命令就展开命令块。

`Ctrl+K` 可以随时聚焦搜索框（侧栏收起时会自动展开）。

### 类型筛选与时间筛选

**类型筛选**是六个 chip，排成两行：`全部` / `Codex` / `Claude` / `Pi` / `DeepSeek` / `Hermes`。

- 「全部」视图下，列表内**按工具分组**，每组带数量
- 切到单一类型或输入了搜索词后，改为**平铺**并给每条加工具徽标

**时间筛选**在下面一行：`不限` / `今天` / `7 天` / `30 天`（按会话最后修改时间算）。
它和类型筛选可以叠加，全文搜索时也是叠加生效的。

**分页只作用于左侧列表**：每页 25 条（底部 `← 第 x/y 页 · 共 n 个`），分组视图下也按总条数翻页，
不会出现每组各自翻页的混乱。全文搜索结果同样按 25 条分页。

**右侧正文不分页**，打开会话就一次性渲染全部消息。这样做的两个好处：
找上下文时不用来回翻页，浏览器的 `Ctrl+F` 也能一次搜到整个会话的内容。
实测最重的会话（199 条消息 / 57 万字）整篇渲染约 0.1 秒，无需担心卡顿。

### 列表里为什么不会重复出现同一条会话

一个会话可能在工作目录里留下**好几个文件**（尤其是 Codex 派生出来的分身在跑任务时），
这些文件里的会话 id 指向同一个父会话。列表已经把它们合并了，规则是：

- **子代理转录不单独显示**。Claude 的 `subagents/agent-*.jsonl`、Codex 的
  `source.subagent` 文件是主代理派出去干活的分身，它们的产出本来就在父会话的工具结果里。
  只有你自己 `/fork` 出来的会话（带 `forked_from_id` 但没有 `subagent` 标记）才单独列出。
- **同一会话的多个文件保留最完整的那个**（体积最大；体积相同取时间更新的）。

所以看到同名条目（如两三条「解析一下xlog」）时，先看 cwd 和时间：**工作目录或时间不同的一定是不同会话**，
只是标题恰好一样（同一个问题在两个目录里各问过一次）。

## 9. 页面内恢复（不弹终端）

不想切终端时用这个：点操作栏的 **`⋯ → 💻 页面内继续对话`**，底部弹出输入栏，直接在这里继续对话。

1. 输入消息，**Enter 发送**，**Shift+Enter 换行**
2. 回复**流式**显示（边生成边出现），跑完自动转成 Markdown
3. 回复会真实写回原会话文件，终端里再 `resume` 也能看到这段

输入栏还有两个下拉：

| 下拉 | 作用 |
|---|---|
| **模型** | 本次调用用哪个模型。选「默认」= 用 CLI 自己的默认 |
| **思考强度** | `low` / `medium` / `high` 等档位，各工具支持的档位不同，列表自动按工具过滤 |

两个都保持「默认」最省事，不要跨工具乱选——不同工具的模型 id 不通用。

**选择会被记住**：按工具各记一份，这次选了 `gpt-6.2-sol`，下次打开别的 codex 会话还是它；
换到 claude 会话则是 claude 自己那份。选过的模型如果之后下线了，会自动退回「默认」。

**下拉里只有「默认」怎么办？**

说明这个工具没读到模型清单。下拉框会显示成**虚线边框**，展开后有一行说明。
每个工具的清单来源不同：

| 工具 | 清单从哪来 |
|---|---|
| claude | `~/.claude/settings.json` |
| codex | `~/.codex/magpie-models.json`；没有就按 `config.toml` 里当前供应商反查 |
| pi | `pi --list-models` |
| dsh | `~/.dsh/profiles/headless/cordis.patch.yml` |

最省事的解法是**把 agent 指向网关**（见第 16 节）：网关有全部供应商的模型池，
指向之后四家的下拉都会列出池子里所有模型，还能用 `group/xxx` 这种路由组名字。

改完 agent 配置不用重启 OpenSession，点「指向」/「还原」时会自动刷新清单。

**行为细节：**

- 运行期间输入框和下拉都锁住，显示「运行中…」，防止并发发送
- 单次运行超过 **10 分钟**自动终止并提示
- 如果回复还没跑完你就点开了别的会话，回复**照常写入原会话文件**，但不会把你拽回去；
  会 toast 提示「XX 已回复，切回该会话可查看」
- **Hermes 会话不支持页面内恢复**（它的存储是只读的），按钮根本不会出现

## 11. 新建会话

点左上 `＋ 新建会话`，三个字段：

| 字段 | 说明 |
|---|---|
| **工具** | Codex / Claude / Pi / Hermes |
| **工作目录** | 会话在哪个目录里跑。输入框带**历史目录下拉**（从你已有会话里取前 30 个）。可以直接写 `~`（家目录）或相对路径，输入框下方会实时显示「将使用：…」解析结果 |
| **第一条消息** | 只有「页面内创建」需要，终端方式忽略 |

底部两个动作按钮：

### ⚡ 页面内创建（推荐）

不弹终端，直接在当前页面把第一条消息跑掉，跑完自动接进列表并打开，输入栏也一并展开，可以接着聊。

- 支持 Codex / Claude / Pi / DeepSeek
- **第一条消息必填**（CLI 的一次性调用没有 prompt 起不来）
- **工作目录必须真实存在**，否则直接报错，**不会**偷偷把会话建到你的家目录去
- 工作目录支持 `~`、`~/子目录`、相对路径（按家目录解析）、带尾斜杠的路径；解析结果会显示在输入框下方，跑起来后顶部 `📁` 后也是真实绝对路径
- 弹窗里按 **Ctrl+Enter**（macOS：⌘+Enter）等同于点这个按钮
- 一次只跑一个创建流；重复点击会提示「上一个会话还在创建中」
- 创建失败会明确标红「未创建」并给出原因，不会停在「新建会话中」的假状态
- 极少数情况下文件落盘比等的时间还慢：此时会显示「已创建 · 列表待同步」并给一个「↻ 重新扫描列表」按钮，不会让你卡在没有输入栏的空页面上

### 启动终端

打开系统终端跑交互式 CLI，后续对话都在终端里。四家都支持（含 Hermes）。这种方式**忽略**「第一条消息」。

> 选 Hermes 时「页面内创建」按钮会变灰并说明原因——它的会话是只读存储，没有页面内适配器。

## 12. 删除与还原

**两个入口，都只是「移入回收站」，不是物理删除。**

| 方式 | 操作 |
|---|---|
| 单条 | 鼠标移到会话条目上 → 右侧出现垃圾桶图标 → 点击 → 确认 |
| 批量 | 筛选栏右侧点 `☑ 多选` → 勾选（或点「全选本页」）→「删除选中」 |

删除后去哪、怎么还原：

| 平台 | 去向 | 还原方式 |
|---|---|---|
| Linux | `~/.local/share/Trash/{files,info}` | 文件管理器打开「回收站」，右键还原 |
| macOS | `~/.Trash`（Finder 的「废纸篓」） | Finder 废纸篓里拖出，或右键「放回原处」 |
| Windows | 系统回收站 | 桌面回收站里右键「还原」 |

**安全边界**（为什么这里不是简单的删除）：

- 只认四家工具的会话目录内的文件，路径穿越（`../../.ssh/id_rsa`）和符号链接逃逸会被拒绝（403）
- 只接受 `.jsonl`；Hermes 只接受 `session_*.json`，索引和诊断 dump 一律拒绝
- 批量删除**逐条校验**：一批里混进非法项，合法的照删，非法的单独报错返回，不会整批失败

> 会话文件是你的历史记录。这个项目刻意不做「彻底删除」按钮——真要物理删，去回收站里清空。

### 13.1 从另一台设备访问（SSH 隧道）

OpenSession 只监听 `127.0.0.1:8347`，**故意不对外暴露**——它没有任何登录鉴权，能读你全部
AI 对话历史、能删除会话、能在本机执行命令。所以不要让监听地址变宽，而是把本机端口
「借」到另一台设备上，用 SSH 隧道。

做法：在**另一台设备**（你的笔记本）上跑：

```bash
# 仓库里自带的脚本，克隆仓库后即可用
./tools/tunnel-client.sh me@<跑 OpenSession 那台机器>

# 然后浏览器打开
# http://127.0.0.1:8347
```

手工等价命令（不想用脚本时）：

```bash
ssh -N -L 8347:127.0.0.1:8347 me@<主机>
```

打开后就是完整界面，功能与在本机用完全一致。`Ctrl+C` 断开。

**为什么走隧道而不是改监听地址**：隧道下浏览器看到的是 `127.0.0.1`，属于「安全上下文」，
剪贴板 API、`EventSource`（页面内恢复的 SSE 流）都能正常工作；而如果把服务绑到局域网地址
再用 `http://192.168.x.x:8347` 打开，浏览器会把它判为不安全来源，复制按钮会降级。

**前提**：那台设备能通过 SSH 连到跑 OpenSession 的机器。同一局域网直接可用；跨公网则需要
本机有公网可达入口（公网 IP 端口映射，或经一台你能登录的公网跳板机）。本机在 NAT 后且
没有映射时，隧道无法直接建立——这是网络条件限制，不是程序问题。

#### 更安全的做法：受限密钥

默认用你自己的账号密钥，意味着能进隧道的人也能拿到 shell。如果只想让对方**看界面**，
可以在服务端生成一把只能转发这**一个端口**、且无法执行命令的密钥：

```bash
# 在服务端机器上
cd ~/.ssh
ssh-keygen -t ed25519 -f opensession_tunnel -N "" -C "opensession-tunnel"
KEY=$(awk '{print $1" "$2}' opensession_tunnel.pub)
echo "restrict,port-forwarding,permitopen=\"127.0.0.1:8347\",permitopen=\"localhost:8347\",command=\"/bin/false\" $KEY opensession-tunnel" >> authorized_keys
chmod 600 authorized_keys
```

把 `opensession_tunnel`（私钥）拷到对方设备，连接时指定：

```bash
./tools/tunnel-client.sh me@<主机> -i ~/.ssh/opensession_tunnel
```

这道配置的效果（均已实测）：

| 尝试 | 结果 |
|---|---|
| 转发 `127.0.0.1:8347` | ✅ 允许，页面正常 |
| 转发别的端口（如 22） | ❌ `administratively prohibited: open failed` |
| `ssh ... "任意命令"` | ❌ 退出码 1，无输出 |

> `permitopen` 是**按字面匹配**的，`localhost:8347` 与 `127.0.0.1:8347` 算两条，都要写。
> 服务只监听 IPv4 回环，写 `[::1]:8347` 也不会通，别白折腾。

#### 客户端脚本参数

| 参数 | 默认 | 作用 |
|---|---|---|
| 第一个位置参数 | 必填 | `user@host` |
| `-p` / `--port` | `22` | 服务端 SSH 端口 |
| `-l` / `--local` | `8347` | 本地端口（本机 8347 被占用时换一个） |
| `-r` / `--remote` | `8347` | 服务端 OpenSession 端口（改过 `OPENSESSION_PORT` 才需要） |
| `-i` / `--key` | — | 指定私钥；也可用环境变量 `TUNNEL_KEY` |

| 全局 | `Ctrl` / `⌘` + `K` | 聚焦搜索框（侧栏收起时自动展开） |
| 手机 | `Esc` | 从正文返回列表 |
| 搜索框 | `Enter` | 全文模式下立即搜索（不等防抖） |
| 搜索框 | `Esc` | 清空关键词 |
| 会话正文 | `Alt` + `↑` / `↓` | 上一条 / 下一条提问 |

> 改过前端代码后，浏览器里要 **Ctrl+Shift+R**（macOS：⌘+Shift+R）强刷一次，否则跑的仍是被缓存的老 JS。

## 15. 手机 / 平板访问

界面按屏幕宽度分三档，不需要单独装 App，用浏览器打开即可。

| 屏幕宽度 | 布局 | 侧栏 |
|---|---|---|
| ≥ 901px | 并排（默认桌面） | 400px，可 `Ctrl+B` 收起 |
| 641–900px | 并排，收窄 | 280px |
| ≤ 640px | **抽屉式**：列表占满整屏 | 全屏 |

**手机上怎么用**：打开先看到会话列表 → 点任意一条，正文从右侧滑入占满屏 →
左上角 `‹ 列表` 返回（或按 `Esc`）。

几个窄屏上的处理：

- **筛选区默认收起**：搜索框下面只有一行「⚙ 筛选 · 条件」，点一下才展开统计计数、
  工具 chip、时间 chip。手机上这三层原来要占近 200px，把列表挤得只剩两三条。
  收起时按钮上是当前条件（如 `Claude · 7 天`），有筛选时描边高亮 —— 不看也知道列表为什么少。
- **代码块**保持不折行，内部横向滑动看（折行会毁掉代码缩进）
- **表格**同理，靠外框横滑；单元格内的标识符不会被拆成碎行
- **恢复命令**那一行在手机上也变成可横滑，比截断成 `...7283-847` 实用
- **长路径链接**会折行，能读完整路径

> 手机上没法用 `Ctrl+B` 折叠侧栏，改用左上角的 `‹ 列表`。
> 从桌面窗口拖窄到手机宽度时，会自动回到列表页（不会出现“正文凭空消失”）。

## 16. 网关：一个端点用上所有供应商

顶栏点最右边的「🔀」按钮打开（`Esc` 关闭）。这一节讲怎么用，实现细节在 README。

### 它解决什么问题

手上有好几家 AI 供应商（官方、中转站、自建），每家的密钥、协议、模型名都不一样。
平时要给每个 CLI 各配一遍，换一家就得改一遍配置。

网关把这些收进一个池子，自家开一个本地端点：

```
http://127.0.0.1:8347/gw/v1/chat/completions    ← OpenAI Chat 协议
http://127.0.0.1:8347/gw/v1/responses           ← OpenAI Responses 协议
http://127.0.0.1:8347/gw/v1/messages            ← Anthropic 协议
```

claude / codex / pi 指向这里，**换供应商不用再动它们的配置**。

### 16.1 添加供应商

「供应商」页签 → 右上「＋ 添加供应商」：

| 字段 | 说明 |
|---|---|
| 名称 | 自己看的名字，随便起 |
| ID | 用作 `provider/model` 前缀。留空自动生成 |
| Chat 基址 | OpenAI Chat 协议的基址，如 `https://api.xxx.com/v1` |
| Anthropic 基址 | Anthropic Messages 协议的基址 |
| Responses 基址 | OpenAI Responses 协议的基址 |
| 模型 | 这家提供哪些模型名，逗号或空格分隔 |
| 密钥 | **可逗号分隔多个，按顺序故障转移** |

**三种基址按需填，不是三选一。** 中转站常常同时给 chat 和 anthropic，
官方 OpenAI 只给 responses —— 填几个它就会几族协议。
只填一个也行，缺的协议网关会自动翻译。

> 不确定填什么？看供应商的「接入文档」，一般会写「OpenAI 兼容」或「Anthropic 兼容」，
> 对应的就是 Chat 基址或 Anthropic 基址。

### 16.1.1 从 magpie 一键导入

如果你已经在用 [magpie](https://github.com/yetone/magpie)，供应商和模型可以直接搬过来：

```bash
node tools/import-magpie.js --dry-run   # 先看会做什么
node tools/import-magpie.js             # 真的导入
```

它读 `~/.config/magpie/`（**只读，不会改 magpie 的任何文件**），把供应商的
三种基址、模型清单、多把密钥都搬进 OpenSession 自己的配置里。

搬的东西：

| 从 magpie | 到 OpenSession |
|---|---|
| `chat` / `anthropic` / `responses` | 同名三个基址字段 |
| `key` + `keys[]` | 合并成密钥列表（按内容去重） |
| `models[]` | 模型清单 |
| `off: true` 且无密钥 | **跳过**（多半是空壳占位） |
| 同名模型被多家提供 | 生成 `group/auto-<模型>` 路由组 |

几个值得知道的行为：

- **模型不全时自动找**：有的供应商在 magpie 的 `providers.json` 里根本不写模型
  （实测 `codex-for-me` 就是空的），脚本会依次从 magpie 写进 pi 的模型表、
  再从用量历史里补，并在导入后把它标在备注里提醒你核对。
- **幂等**：再跑一遍不会重复添加，密钥也按内容去重。magpie 以后加了新供应商，
  重新跑一次就同步过来了。
- **不覆盖你的改动**：已存在的路由组只补成员，不会把你改过的路由模式改回去。
- **不动默认供应商**：只有你原本没设过（或指向的已不存在）时才会设，
  取 magpie 里用量最多的那家。

> `--no-groups` 不生成自动路由组；`--from <目录>` 从别处的 magpie 配置读。

### 16.2 多把密钥：额度用完自动换

同一家填多个密钥（编辑供应商时用逗号分隔），会**按顺序使用**：
第一把返回额度用完（429）或服务端错误（5xx），自动换下一把重试，你的 CLI 看不到错误。

这正是「一个账号额度用完换另一个」的做法 —— 不用手动改配置。

> 只有 429 / 408 / 5xx 才换 key。**密钥无效（401/403）会直接把上游原话报给你**，
> 因为换 key 也没用，你还得多等几轮才知道真正原因。

### 16.3 测连通

每家供应商右侧「测连通」，发一个最小请求看能不能通。

| 结果 | 含义 |
|---|---|
| 绿 · 带延迟 | 通了，延迟是首字时间 |
| 红 · 401 / 403 | 密钥无效或没权限 |
| 红 · 404 | 基址路径不对（常见是 `/v1` 多写或少写） |
| 红 · 超时 | 网络不通，或基址写成外网域名但本机走不了 |

**一家有多个模型时会自动往下试。** 中转站的模型经常悄悄下线，只测第一个模型
会把一家**能用的**供应商误判成「挂了」——实测有一家 13 个模型里 3 个已下线，
而排在第一个的正好是其中之一。

所以：失败就换下一个，最多试 3 个，只要有一个通就算这家没问题。
提示里会写清楚「哪个不通、换到哪个通的」，比如
`连通 · 200 · 2588ms · gpt-5.5（codex-auto-review 不通，换到这个）`。

全都不通时会列出各自的状态码，这时才需要怀疑是密钥或基址的问题：

```
失败 503：Service temporarily unavailable · codex-auto-review=503，gpt-5.6=503，gpt-6=503
```

### 16.4 路由组：给一组模型起一个名字

「路由组」页签。一个组把**几家几个模型**当成一个名字，agent 那边只写 `group/名字`。

组里的成员按模式挑：

| 模式 | 行为 |
|---|---|
| `order` | 按顺序用第一个，失败换下一个 |
| `rotate` | 每次调用轮换，分摊用量 |
| `usage` | 挑用量最少的那家 |
| `smart` / `pace` | **降级**为 order / usage（界面标「降级」） |

> `smart` / `pace` 在 magpie 里靠探测各家剩余额度决定，OpenSession 不探测余额，
> 所以**如实标注降级**，不假装支持。

用处：比如建一个 `group/fast`，装上三家的旗舰模型，模式 `rotate`。
agent 写 `group/fast` 就会在三家之间轮着用，单家限流也不怕。

### 16.5 Agent 指向

「Agent 指向」页签，列出本机装了的 CLI。每行一个开关：

| Agent | 能做什么 |
|---|---|
| claude | 选模型 + 开关 |
| codex | 选模型 + 开关 |
| pi | 选模型 + 开关 |
| dsh | **只读**（它的供应商在多层嵌套 YAML 里，暂不写） |

**开关拨开**，那一家的请求就走本网关；**拨回去**，配置回到你拨开之前的样子。
开启期间调过模型的，用旁边那个「还原」退回上一次改动之前 —— 两者不一样：

| 动作 | 回到哪里 |
|---|---|
| 开关关掉 | 你**拨开这扇门之前**那一刻（哪怕是几天前、中间改过多少次模型） |
| 「还原」 | **上一次改动之前**（含开启后改模型那一次） |

都不是回到厂商默认，所以原来配的中转站不会丢。

**模型点按钮选，不用背名字**。点模型字段会弹出一个按供应商分组的面板，
顶上能搜索，组名后面标着这家有几个模型。选定只记下来，拨开关那一刻才真正写配置。

**每个工具各用各的模型**，不是全局一个。

为什么不能共用一个：Claude 走 Anthropic 协议、Codex 只认 Responses、
Pi 的清单是网关注入的 —— 同一个模型名并非处处可用。共用一份的结果是要么
「改成 A 家的模型，B 家一启动就报模型不存在」，要么每次换工具都得重填。

每个工具的模型记在 `~/.config/opensession/gateway.json` 的 `agentModels` 里，
下次打开页面自动回填它自己的值。

> 回填的是**实际生效的模型**。Claude 显示的是 `env` 里那四档
> `ANTHROPIC_DEFAULT_*_MODEL` 的值（不是配置顶层的 `model` 字段）——
> 只显示顶层会把「改成功了」和「没改到」看成一样。
> 如果现有模型不在网关的模型清单里（比如它走的是别家的中转站），
> 字段会留空并提示「另选一个」，避免你一点就报错。

**状态行怎么读**：

| 显示 | 意思 |
|---|---|
| 绿「已接入」 | 请求真的打到本网关，地址对、协议对 |
| 琥珀「地址少了 /gw」 | 指到了本网关端口但路径不对，**每条请求都会 404** —— 关掉再开即可修正 |
| 灰「未接入」 | 没走网关，后面跟着它现在实际用的地址与模型 |

> 早先版本写错了基址（少一段 `/gw`），界面看着是「已指向」而实际全 404。
> 现在判定要看地址真的对不对，不再只看 provider 叫什么名字。

**改之前会自动备份**，位置 `~/.config/opensession/agent-backups/`。

> codex 的配置里有上百个 `[projects.*]` 段（每行一个你打开过的目录）。
> 指向网关只改顶上的两个赋值和一个自己的段，那些 `[projects.*]` 与注释全保留。

### 16.6 用量

「用量」页签：调用次数、失败率、token 数、平均延迟，按天 / 按供应商 / 按模型三个维度。

**只记量纲，不记内容** —— 记的是「谁在什么时候用了多少 token、延迟多少、状态码几」，
**不记你问了什么、模型答了什么**。所以这个页面可以随便截图。

### 16.7 接入：别的机器怎么用

「接入」页签给的是现成配置片段，复制粘贴到别的项目里就能用。

注意网关只监听 `127.0.0.1`，**别的机器访问不到**。要从另一台设备用，
先按 [13.1 节](#131-从另一台设备访问ssh-隧道) 建 SSH 隧道，再把片段里的地址相应改掉。

### 16.8 常见问题

**Q：拨开开关后，claude 报连不上？**
先确认网关顶部开关是「已启用」。没启用时 `/gw/*` 一律返回 503，不会连上游。
如果状态行显示琥珀色「地址少了 /gw」，那是旧版本写坏的配置 —— 关掉再开一次即可修正。

**Q：填了三家，`provider/model` 报 404？**
检查模型名是否写进了那家供应商的「模型」列表。网关只认声明过的模型名。

**Q：改完 `~/.config/opensession/gateway.json` 没生效？**
不用重启，服务会按文件修改时间自动重读。如果还是旧的，点顶栏刷新按钮。

**Q：还原 pi 之后 `models.json` 里的供应商全没了？**
这是早期 bug，已修复（备份查找误把 settings 当成 models）。
现在还原前会**校验备份内容形状**，对不上就跳过并提示，不会硬写。
如果已经踩到，`~/.config/opensession/agent-backups/` 里找 `pi-*.json` 手工改回来。

## 17. 常见问题

**Q：页面打开是空白，左侧一个会话都没有？**
先看五个工具目录存不存在（`~/.codex/sessions`、`~/.claude/projects`、`~/.pi/agent/sessions`、`~/.dsh/sessions`、`~/.hermes`）。
一个都没有说明你还没在那台机器上用过这些 CLI，不是程序的问题。有一个但没列出来，看服务日志：

```bash
journalctl --user -u opensession -f                    # Linux
tail -f ~/Library/Logs/opensession/opensession.err.log   # macOS
# Windows：直接看 `%USERPROFILE%\.opensession\` 下的日志，或前台手跑 node 看输出
```

**Q：点「页面内恢复」报「未找到命令」？**
服务进程的 `PATH` 里没有那个 CLI。开机自启的服务 `PATH` 往往只有 `/usr/bin:/bin`，
而 `codex` / `claude` / `pi` 通常装在 `~/.npm-global/bin` 这类目录。重跑 `./install.sh` 会自动补上；
手工确认：`systemctl --user show-environment | grep PATH`。

**Q：页面内恢复没反应、也没报错？**
通常是请求体不合法，后端返回了 JSON 错误而不是 SSE 流。看浏览器控制台的 Network 面板里
`/api/embed` 那条请求的响应体，会有明确的 `error` 字段。

**Q：新建会话报「工作目录不存在或不是目录」？**
这是刻意设计：目录打错时**不会**把会话静默建到家目录去。改成真实存在的目录再试。

填 `~`、相对路径、带尾斜杠的路径都是支持的，输入框下方会实时显示会解析成什么。如果提示里带「（由 xxx 解析而来）」，
说明你写的是相对路径 —— 它按**家目录**解析，不是按你当前所在的项目目录。想让会话在某个项目里跑，就写全绝对路径。

**Q：新建会话后没有输入栏 / 发消息报错？**
正常情况创建完会自动打开新会话并展开输入栏。如果界面停在「已创建 · 列表待同步」，说明会话文件还没落盘到能被扫描到的位置，
点界面上的「↻ 重新扫描列表」；仍不行就点右上角 `↻` 刷新，或先用「▶ 终端恢复会话」接上。

**Q：macOS 上点「终端恢复」没弹窗口？**
`.command` 文件由系统默认终端打开。若你的默认终端是某个未注册的第三方终端，可能在设置里
指定一下。另外 Windows / macOS 侧都只做过静态与模拟验证，真机首次使用建议先点一次「复制命令」
手动跑，确认命令本身没问题。

**Q：删掉的会话能恢复吗？**
能。它们都在回收站里，见 [11. 删除与还原](#11-删除与还原)。

**Q：能从别的机器访问吗？**
能，但要走 **SSH 隧道**，见 [13.1](#131-从另一台设备访问ssh-隧道)。服务本身只监听 `127.0.0.1`，
**不要**改成 `0.0.0.0` 直接暴露——它没有鉴权，能读你所有对话历史、能删会话、能在本机执行命令。
隧道的好处是通道由 SSH 的密钥认证守门，且浏览器仍以为是本机地址，功能不打折。

**Q：会往我的会话文件里写东西吗？**
只有一种情况会：你在「页面内恢复」或「页面内创建」里发了消息。其余所有操作（浏览、搜索、导出、
复制命令）都是只读。删除是把文件移进回收站，不改文件内容。

## 附录：名称沿革与命令对照

这个工具在 2026-11-23 一天里改过两次名，最终定名 **OpenSession**：

| 阶段 | 英文名 | 命令 | 服务 |
|---|---|---|---|
| 最初 | `agenthist` | `agenthist-open` | `agenthist.service` |
| 中间 | Agent Sessionary | `asry-open` | `asry.service` |
| **当前** | **OpenSession** | **`opensession-open`** | **`opensession.service`** |

### 从任一旧版本升级

```bash
./install.sh --uninstall          # 先撤掉旧服务（在旧目录里执行）
./install.sh                      # 在新目录里装一遍
```

旧命令与旧配置**不会自动删除**。如需清理：

```bash
# agenthist 时代
rm -f ~/.local/bin/agenthist ~/.local/bin/agenthist-open \
      ~/.local/bin/agenthist-service ~/.local/bin/agenthist-web
rm -rf ~/.config/agenthist ~/.cache/agenthist-chrome

# Agent Sessionary 时代
rm -f ~/.local/bin/asry-open ~/.local/bin/asry-service
rm -rf ~/.config/agent-sessionary ~/.cache/asry-chrome
```

### 配置与环境变量对照

| 项目 | agenthist | Agent Sessionary | OpenSession |
|---|---|---|---|
| 环境变量前缀 | `AGENTHIST_` | `ASRY_` | `OPENSESSION_` |
| 项目位置记录 | `~/.config/agenthist/appdir` | `~/.config/agent-sessionary/appdir` | `~/.config/opensession/appdir` |
| Chrome 配置 | `~/.cache/agenthist-chrome` | `~/.cache/asry-chrome` | `~/.cache/opensession-chrome` |
| Windows 数据 | `%USERPROFILE%\.agenthist` | `%USERPROFILE%\.agent-sessionary` | `%USERPROFILE%\.opensession` |
| macOS 日志 | `~/Library/Logs/agenthist/` | `~/Library/Logs/agent-sessionary/` | `~/Library/Logs/opensession/` |

**会话数据不受影响** —— 这个工具从不搬动会话文件，改名只涉及它自己的命令、服务和配置。
你的 Codex / Claude / Pi / DeepSeek Harness / Hermes 会话一条都不会丢。
